# 领域文档

本仓库采用单上下文布局。

## 探索代码前

- 读取根目录的 `GLOSSARY.md`，了解领域术语。
- 读取 `docs/adr/` 中与当前任务相关的架构决策。

如果这些文件不存在，直接继续，不提示缺失，
也不预先建议创建。领域建模技能会在术语或决策确定时按需创建。

## 文件布局

- `GLOSSARY.md`：全仓库的领域术语表。
- `docs/adr/`：架构决策记录，文件名采用 `0001-<slug>.md` 格式。

## 使用领域术语

在任务标题、重构建议、假设和测试名称中使用术语表定义的词汇。
避免改用术语表明确排除的同义词。

遇到未收录的概念时，先判断是否引入了项目不使用的词汇；
确有缺口时，记录为后续领域建模事项。

## 架构决策冲突

如果建议与已有 ADR 冲突，明确指出对应 ADR、
冲突内容及重新讨论的理由，不静默覆盖既有决策。
