# 文本检测引擎规格

Status: resolved

实施记录：2026-10-20，初始引擎由 `0ee3fd7` / `07d9b26` 完成。本页保留需求形成时的内容；生成式 Judge、模型输出和旧配置相关要求已由 [Jev 后续规格](../jev-judge/spec.md) 替代。当前使用方法见 [引擎文档](../../docs/text-engine.md)，能力边界见 [交接状态](../../docs/status.md)。

## Problem Statement

Agent 会读取工具返回的不可信文本，其中可能包含要求忽略原任务、改变目标或执行越权动作的投毒指令。项目目前只有生命周期接线和检测接口占位，无法判断一段文本是否正在尝试操纵 Agent，也无法区分攻击、正常引用与检查失败。

使用者需要一个独立、可测试的文本检测引擎，将规则匹配证据与语义判断结合起来。规则未命中不能证明安全，模型判断也不能覆盖其他阶段的失败信息。引擎应返回可解释的检测事实，供外部处置层决定是否告警或阻断。

## Solution

构建独立于 OpenCode hook 的文本检测引擎。调用方传入文本、来源和可选任务上下文，引擎使用初始化时加载的本地 YAML 规则快照，执行关键词检测、正则检测及一次独立的语义裁判判断，再返回整体结论、各阶段执行状态、命中证据和规则快照版本。

首版主要用于工具返回内容引起的记忆投毒检测，不涉及持久记忆文件。检测目标是识别试图操纵 Agent 的不可信指令，区别于安全教程等材料对攻击指令的引用。整体结论为“有风险”“未发现风险”或“不确定”；检查不完整不得返回“未发现风险”。

## User Stories

1. 作为检测域的调用方，我希望只提供待检文本、来源和可选任务上下文，以便不必让检测引擎理解 OpenCode 原始事件。
2. 作为检测域的调用方，我希望引擎不自动读取完整会话，以便控制传给检测服务的数据范围。
3. 作为安全维护者，我希望检测工具返回文本中的投毒指令，以便识别不可信内容对 Agent 后续行为的操纵。
4. 作为安全维护者，我希望区分攻击指令和正常引用，以便降低教程、分析报告及示例文本引起的误报。
5. 作为规则维护者，我希望从本地 YAML 加载规则，以便通过可审查的文本维护检测条件。
6. 作为规则维护者，我希望关键词和正则共用规则标识、标题、检测域及严重程度等元数据，以便统一管理检测发现。
7. 作为规则维护者，我希望关键词按字面子串匹配，以便明确理解每条规则的行为。
8. 作为规则维护者，我希望关键词默认忽略英文大小写，以便覆盖普通大小写变化。
9. 作为规则维护者，我希望选择任一关键词命中或全部关键词命中，以便表达简单的单条件与组合条件。
10. 作为规则维护者，我希望每条正则规则包含一个表达式及显式选项，以便描述结构化文本模式。
11. 作为规则维护者，我希望初始化时发现重复 ID、缺失字段、未知字段及非法正则，以便在检测开始前修正规则。
12. 作为引擎调用方，我希望规则有错误时初始化整体失败，以便不在不知情的情况下使用残缺规则集。
13. 作为引擎调用方，我希望每次检测使用固定规则快照，以便同一次运行不受文件中途修改影响。
14. 作为安全分析者，我希望结果记录规则快照版本，以便复现和解释检测结果。
15. 作为安全分析者，我希望每条有效、未超限的文本都经过三类检测，以便观察每种方法的独立贡献。
16. 作为安全分析者，我希望未命中规则的文本仍交给语义裁判，以便发现规则没有覆盖的改写攻击。
17. 作为引擎调用方，我希望每条文本只进行一次语义裁判调用，以便避免每条 YAML 规则都触发模型请求。
18. 作为安全分析者，我希望语义裁判不预先看到规则命中结果，以便比较独立判断与模式匹配的差异。
19. 作为集成方，我希望通过注入适配器显式指定模型服务、模型名称和凭据，以便独立管理检测服务。
20. 作为数据提供方，我希望待检内容与检测指令分开组织且语义裁判没有工具权限，以便限制被检文本的影响范围。
21. 作为集成方，我希望语义裁判返回固定结论、简短理由及原文证据，以便可靠解析结果。
22. 作为安全分析者，我希望区分语义不确定、服务故障和无效输出，以便知道不确定结果的原因。
23. 作为安全分析者，我希望正则未命中但语义裁判判断有风险时整体仍为有风险，以便不漏掉没有模式命中的语义攻击。
24. 作为安全分析者，我希望规则命中而语义裁判判断正常时保留冲突，以便不静默丢弃规则证据。
25. 作为安全分析者，我希望关键词及正则结果包含命中原文和位置，以便核查规则实际匹配了什么。
26. 作为安全分析者，我希望模型引用的证据能对应原文，以便不把模型生成的内容当作真实证据。
27. 作为引擎调用方，我希望超长文本返回明确的不确定原因而非被截断，以便知道输入没有完整接受检查。
28. 作为引擎调用方，我希望区分阶段完成、失败和未执行，以便不把空发现列表误当作检查通过。
29. 作为集成方，我希望引擎不自行保存全文或写检测日志，以便由调用方控制存储与审计。
30. 作为处置层调用方，我希望收到检测发现而非引擎自行阻断，以便按业务策略处理风险与不确定结果。
31. 作为开发者，我希望用固定规则和可控语义裁判测试公开行为，以便在不调用真实模型时稳定验证逻辑。
32. 作为安全维护者，我希望单独重复评测真实模型的误报、漏报及耗时，以便判断语义检测效果。

## Implementation Decisions

### 模块与接口边界

- 文本检测引擎接收独立文本输入，不接收原始安全事件；事件提取和来源标记属于检测域或适配层。
- 输入包含待检文本、来源及可选任务上下文，不自动获取完整会话。
- 调整现有规则求值契约，将原始事件输入改为文本检测输入，并提供可表达整体结论、阶段状态和证据的公开结果。
- 本地规则源、关键词匹配、正则匹配、语义裁判及结果汇总作为引擎内部职责，通过一个主要公开测试入口验证。
- 复用现有语义裁判抽象，扩展输入以支持来源和上下文，扩展输出以支持结构化理由和证据。
- 语义裁判使用独立检测指令配置，不再将其作为每条 YAML 规则分别调用模型的一种执行方式。
- 引擎返回检测事实，不执行告警或阻断；处置决定仍由外部策略负责。

### 输入边界

- 单次待检文本上限为 16,000 个 Unicode 码点，作为可配置的首版工程默认值，不按 UTF-16 单元或字节计数。
- 超限返回“不确定：文本超限”，不静默截断、不调用语义裁判，也不将局部检查描述为完整检查。
- 首版不做分块、自动翻译、拼音转换、Base64 解码或模糊匹配。

### 规则模型与加载

- 规则采用项目自有的最小 YAML 模型，保留 ATR 适配入口，不宣称原始 ATR 规则兼容。
- 规则元数据包含模式版本、唯一 ID、标题、启用状态、检测域及严重程度。检测引擎不依赖 hook；现有 hook 元数据如需保留，只服务于调用方选取适用规则，不承担正文提取职责。
- 关键词规则采用字面子串匹配，默认忽略英文大小写，支持“任一关键词”或“全部关键词”模式。一个多词短语作为一个完整匹配项，不自动拆词。
- 正则规则包含一个表达式及显式匹配选项。支持的选项须由实现明确声明并校验。
- 初始化时读取本地 YAML、校验并生成固定规则快照；修改规则后重新初始化。
- 重复 ID、缺失字段、未知字段、非法表达式及不支持选项均使本次初始化失败，不静默跳过错误规则。
- 未成功初始化的引擎不可提供成功检测结果；加载失败作为初始化错误报告，不伪装成“没有命中”。
- 每次检测关联所用快照版本。版本生成细节由实现选择，但必须能够标识实际参与检测的规则快照。

### 三类检测与语义裁判

- 对通过输入校验、未超限且引擎已初始化的文本，执行关键词、正则和语义裁判，分别保留结果；正常的规则命中与未命中均不跳过语义裁判。
- 关键词与正则用于产生模式证据，不将未命中表述为“判断无风险”。
- 每条文本调用一次语义裁判，综合检查适用检测目标，不按规则条数发起模型请求。
- 语义裁判独立接收文本、来源和必要任务上下文，不预先接收关键词或正则命中结果。
- 通过调用方注入的适配器接入模型，显式配置模型服务、模型名称及凭据，不自动复用 Agent 完整会话或模型配置。
- 检测指令与待检内容分开组织；语义裁判不开放工具调用。
- 模型输出为固定结构，包含三态结论、简短判断理由及允许为空的可疑原文证据。
- 输出无法解析、必需字段缺失或结论非法时，记录“语义裁判输出无效”，不从自由文本猜测结论。
- 区分模型服务故障与模型正常返回“语义不确定”。

### 结果汇总

| 条件 | 整体结论 |
| --- | --- |
| 必需检查完整，语义裁判判断攻击，无论关键词、正则是否命中 | 有风险 |
| 规则命中，语义裁判判断正常 | 不确定，保留冲突证据 |
| 规则未命中，语义裁判判断正常，所有检查完成 | 未发现风险 |
| 语义裁判返回不确定 | 不确定 |
| 必需阶段失败、输出无效或检查不完整 | 不确定，并保留已经产生的检测发现 |
| 文本超过长度上限 | 不确定，标记文本超限及未执行阶段 |

- 正则正常完成但未命中与正则执行失败必须严格区分。前者不否定语义裁判的风险结论；后者属于检查不完整。
- 各阶段至少可区分完成、失败及未执行。语义判断结论与技术执行状态分别记录。
- 检查完整是输出“未发现风险”的必要条件；该结论不是安全保证。
- 首版不新增高确定性规则直接定案、自动覆盖冲突或数值加权打分策略。

### 证据与数据存储

- 关键词和正则的命中证据包含规则 ID、命中原文和原文位置。
- 原文位置的计数与区间约定必须在公开契约中明确，并通过包含非 BMP 字符的测试验证，不混用字节、码点和 UTF-16 位置。
- 语义裁判证据必须能对应待检原文。无法对应时标记证据无效，不将模型生成文本作为原文证据；不得据无效证据将不完整检查宣称为通过。
- 引擎返回检测结果，默认不保存待检全文、不自行写检测日志。持久化与审计由调用方负责。

### 耗时策略

- 首版不设置引擎整体超时，也不设置正则执行时限。
- 语义裁判默认不自动重试，不因规则数量增加模型调用次数。
- 无超时不意味着无限输入，仍执行文本长度上限。
- 不引入原先讨论过的整体 5 秒或正则 100 毫秒限制；这些限制已经被明确否决。

## Testing Decisions

- 已与用户确认：以初始化并调用文本检测引擎的公开入口作为主要测试边界，使用真实本地 YAML 和可控语义裁判替身，验证整体结论、证据和错误状态；真实模型单独重复评测。
- 优先验证外部行为，不断言内部函数调用顺序、私有类结构或与实现重复的细节。不为关键词、正则和汇总器额外暴露仅供测试使用的接口。
- 沿用项目现有 Node.js 测试工具及断言风格。已有运行时测试通过公开检查入口验证检测域路由和“未实现不是通过”；已有适配层测试使用可控依赖验证响应流保留与卸载行为，可作为本次依赖替身测试的先例。
- 初始化行为覆盖有效规则、重复 ID、缺失及未知字段、非法正则、不支持选项、整体失败、快照稳定性及重新初始化后的版本变化。
- 关键词覆盖中文、英文大小写、多词短语、任一及全部模式、正常未命中、证据原文与位置。
- 正则覆盖表达式及选项生效、正常未命中、模式命中证据，以及可控阶段失败与正常未命中的区别。
- 通过可控语义裁判验证有效输入无论是否命中规则均只调用一次，且不会收到规则命中结果或自动获取的完整会话。
- 覆盖结构化攻击结论、正常结论、不确定、服务异常、非法结构和无法对应原文的证据。
- 完整覆盖汇总表，尤其验证“正则未命中、语义裁判判断有风险”必须得到“有风险”，规则命中与正常语义判断冲突时保留双方证据。
- 输入边界覆盖上限内、恰好上限和超限，以及非 BMP 字符的码点计数。超限必须不调用模型，且不将部分结果当作完整结论。
- 正常检测返回规则快照版本、各阶段状态及检测证据。检查失败不能返回“未发现风险”。
- 不使用真实灾难性正则或永不返回的模型调用拖住测试；无超时策略不要求以无法终止的测试验证。
- 真实模型评测使用明确恶意指令、安全教程引用、正常工具结果、规则未覆盖的改写攻击、中英文及混合文本。重复运行并记录误报、漏报和耗时，不要求每次措辞或结论完全一致。
- 真实模型需要显式配置并单独执行，不作为日常确定性测试的默认网络依赖。尚未约定模型、数据集或量化通过阈值，不虚构这些指标为已确认要求。

## Out of Scope

- 编写本规格不包含功能实现。
- 持久记忆文件投毒、文件完整性监控。
- 四个检测域的完整威胁检测、资源预算统计、操作系统隔离和跨事件攻击关联。
- OpenCode 事件正文提取、HTTP/SSE 解析、WebSocket 帧重组及流式输出交付前拦截。
- 处置策略执行、自动阻断、审计存储、通知和全文日志。
- 完整 ATR 语义兼容、ATR 原始规则库导入或远程规则下载。
- 热更新、复杂规则组合语言、规则脚本、自定义可执行函数。
- 长文本分块、自动解码、翻译、拼音与模糊匹配。
- 检测超时、正则执行时限、模型自动重试、按风险跳过语义裁判及性能优化策略。
- 每条 YAML 规则单独调用模型、模型工具调用。

## Further Notes

- 当前实现仅有接口占位和四个返回未实现状态的检测域。现有空发现列表不能作为安全判定依据。
- “记忆投毒”遵循现有领域定义：本功能关注工具返回内容污染上下文，不扩大为持久记忆文件保护。
- 无检测时限意味着耗时正则或缓慢模型请求可能持续阻塞等待检测结果的 hook；这是已明确接受的首版取舍，不得在实现时自行加入之前否决的时限。
- 语义裁判仍可能受被检内容影响，结构化输出或指令分隔不能证明其判断可靠，因此需要保留独立规则证据并单独评测。
- 模型服务具体适配器、模型选择、正则选项集合和位置坐标细节尚无指定值；实施时应明确契约，避免将未讨论的选型表述为既有决定。
- 本规格按本地 Markdown 任务跟踪约定发布，状态为 ready-for-agent；不自动创建实现任务或发起远端 issue。
