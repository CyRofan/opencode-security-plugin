# 04: 接入真实模型 Judge

**What to build:** 调用方显式配置模型服务、模型名称和凭据并注入适配器后，可以通过同一个文本检测入口完成真实语义检测，获得经过统一校验和汇总的结果，而无需依赖 OpenCode 的完整会话或默认模型配置。

**Blocked by:** 03 — 完成 Judge 结果校验与三类结果汇总。

**Status:** claimed

- [ ] 在本任务明确一个具体模型服务适配器选型及请求、响应契约，说明配置方式，不将尚未决定的模型或服务表述为已有要求。
- [ ] 通过调用方注入适配器接入语义裁判，显式配置服务地址、模型名称和凭据；不自动复用 Agent 模型配置或读取完整会话。
- [ ] 每条有效文本发起一次语义判断，而非每条 YAML 规则一次；Judge 使用独立检测指令配置。
- [ ] 请求中区分检测指令、待检文本、来源及必要任务上下文，针对操纵 Agent 的不可信指令进行判断，同时区分安全教程和攻击引用。
- [ ] 不开放工具调用，不向 Judge 提供关键词或正则命中结果，不默认保存待检全文或记录含正文、凭据的日志。
- [ ] 将真实服务输出送入任务 03 的统一结构与证据校验；服务异常、无法解析、非法结论等使用现有失败语义，不伪装成正常结论。
- [ ] 不添加检测超时，不自动重试；检查所选客户端，避免无意引入与此约定冲突的默认超时或重试行为，并如实说明服务自身约束。
- [ ] 使用可控模型传输替身，从公开引擎入口验证请求数据边界、单次调用、有效输出、服务故障和无效响应；日常测试不依赖真实模型或网络。
- [ ] 提供显式配置后运行真实检测的使用说明和可验证调用方式；不把真实请求作为默认测试前置条件，不提交真实凭据。
- [ ] 本任务不依赖正则实现，因此只被任务 03 阻塞；与任务 02 使用同一公开引擎入口及既有结果契约保持兼容。
