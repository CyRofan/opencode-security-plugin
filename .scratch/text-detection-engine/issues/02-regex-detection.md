# 02: 接入正则规则与原文证据

**What to build:** 调用方使用同一个文本检测入口，可以在一次检查中执行关键词和正则规则，获得各自的命中证据及阶段状态。正则规则同样参与初始化校验与固定快照管理。

**Blocked by:** 01 — 关键词文本检测的最小闭环。

**Status:** claimed

- [ ] 扩展本地 YAML 规则支持一个正则表达式及显式匹配选项，与关键词共用规则元数据、启用状态及快照机制。
- [ ] 明确支持的正则选项；非法表达式、不支持选项、缺失或未知字段等使初始化整体失败，不在检测时才发现配置错误，不静默跳过。
- [ ] 从公开检测入口返回正则规则 ID、命中原文、原文位置及阶段执行状态，与关键词使用一致的位置约定。
- [ ] 正常未命中记录为阶段完成且无命中，执行失败记录为阶段失败；不将正则未命中表述为“判断无风险”。
- [ ] 同一次检测可执行关键词和正则，正常命中或未命中均不跳过语义裁判，不增加每条文本的一次语义裁判调用次数。
- [ ] 明确匹配过程不修改输入文本，重复检测行为不因匹配器残留状态而改变。
- [ ] 通过公开入口及真实 YAML 验证表达式、显式选项、正常未命中、禁用规则、命中证据与含非 BMP 字符的原文位置。
- [ ] 验证规则快照反映实际正则配置，文件修改不影响已初始化快照，重新初始化后使用更新后的规则。
- [ ] 以可控方式验证失败状态，不使用灾难性正则拖住测试；不增加正则执行时限或整体检测超时。
- [ ] 延续现有统一阶段结果契约，不要求任务 03 已完成才能交付；完整冲突汇总由任务 03 的统一结果语义覆盖。
