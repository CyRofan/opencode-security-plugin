# 01: 关键词文本检测的最小闭环

**What to build:** 调用方可以初始化独立于 OpenCode hook 的文本检测引擎，从本地 YAML 加载关键词规则，传入文本、来源和可选任务上下文，通过注入的可控语义裁判获得可解释的检测结果。本任务交付可运行、可验证的最小闭环，真实模型接入和完整汇总边界由后续任务扩展。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 提供初始化及文本检测的公开入口，不要求调用方传入原始安全事件，不自动获取完整会话。
- [x] 调整现有占位契约，使规则匹配、语义裁判及结果结构可以支持独立文本输入；保持原有插件骨架的类型检查和测试通过。
- [x] 通过真实本地 YAML 加载关键词规则，公共元数据包含模式版本、唯一 ID、标题、启用状态、检测域和严重程度；采用项目最小规则模型，不声称 ATR 兼容。
- [x] 关键词采用字面子串匹配，默认忽略英文大小写，支持任一及全部关键词命中；多词短语不自动拆词，禁用规则不参与检测。
- [x] 初始化校验重复 ID、必需字段、未知字段及关键词规则结构；任一无效规则使初始化整体失败，不静默跳过，不提供成功检测结果。
- [x] 初始化生成固定规则快照；修改本地文件不影响已初始化实例，重新初始化后可使用新快照，每次检测结果携带实际规则快照版本。
- [x] 匹配结果包含规则 ID、命中原文及原文位置；明确公开的位置坐标和区间约定，并验证非 BMP 字符不会导致证据位置错位。
- [x] 默认最多接受 16,000 个 Unicode 码点，支持配置；覆盖上限内、恰好上限及超限。超限不截断、不调用语义裁判，返回不确定原因和未执行阶段。
- [x] 对有效未超限文本，无论关键词是否命中，均调用一次注入的可控语义裁判；不把命中结果传给它，不按规则数量增加调用次数。
- [x] 交付基本结果闭环：完整检查且语义裁判判断攻击时返回有风险；无模式命中且语义裁判判断正常时返回未发现风险；尚未完成的必需检查不得伪装成通过，相关完整边界由任务 03 验收。
- [x] 用公开入口、真实 YAML 和可控语义裁判验证中文、英文大小写、完整短语、任一及全部模式、正常未命中、快照行为和输入边界，不断言内部实现结构。
- [x] 不设置检测超时，不自动重试，不保存待检全文，不自行写检测日志或执行阻断；不添加分块、解码、翻译及模糊匹配。

## Comments

实现已完成。通过公开引擎入口、真实本地 YAML、可控 Judge/传输及本地 HTTP 服务验证；规范与规格两路审查均无发现。
