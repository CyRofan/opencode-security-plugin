# session.prompt 记忆投毒检测完善讨论

Status: resolved
Type: grilling
Date: 2026-10-26

## 目标

用户希望完善记忆投毒检测域在 session.prompt 的检测逻辑、处理逻辑及规则覆盖。四轮设计决定已由用户逐项确认，讨论已收敛。本文件记录设计与验收约定，不替代后续实现规格；本次讨论未修改运行时代码或启动模型评测。

正式实现规格已发布：[session.prompt 记忆投毒检测与输入替换完善规格](spec.md)，状态以该规格为准。讨论 resolved 仅表示设计确认结束，不表示功能已实施。

## 已确认设计摘要

| 方面 | 约定 |
| --- | --- |
| 输入范围 | 仅当前 session.prompt 用户正文；不读取会话历史、附件、技能或其他 hook 内容。 |
| 检测 | 本地关键词／正则提供证据；有效未超限正文每次检测一次 Jev 原生 Choice。 |
| 汇总与处置 | 最终 malicious 才整条固定中性替换；benign 保留；规则冲突、语义 uncertain 和检查未完成保留正文并明确告警，不宣称安全。 |
| 规则覆盖 | 六类用户输入模式，参考 ATR 后按项目 YAML 改编，覆盖中文、英文和混合输入。每类有攻击与正常对照；不增加自动解码或完整 ATR 兼容。 |
| 用户通知 | 为已连接 OpenCode TUI 增加原生可见提示，同时保留结构化日志；不展示攻击原文，不承诺断线补投。 |
| 真实评测预算 | 60 条独立标注样本，六类各 5 条攻击与 5 条正常，每条 3 轮，共 180 次真实 EdgeOne Jev 请求。 |
| 评测验收 | 每轮正常样本 0 次误替换，攻击样本至少 90% 明确 malicious 并触发替换；无技术未完成，单列 uncertain、误告警和耗时。 |
| 宿主验收 | 验证实际接纳保存和发往模型的正文已替换，正常输入不变，并验证 TUI 提示及清理。 |

真实模型的样本标注不发送给 Judge，不使用真实用户会话。三轮是明确约定的重复评测，不是失败自动重试；出现失败如实记录，不自动补跑突破调用预算。验收指标是本轮样本集标准，不改变运行时置信度判定，也不外推总体准确率。

## 现状核对

- 当前实现提交为 9a5e091。已有正文提取、固定 user-input 来源、本地 YAML 快照、关键词／正则和一次 Jev Choice，以及结果映射与结构化警告。
- 仅检测当前正文；其他入口保持占位。运行时 SecurityDecision 尚未接入，malicious、语义 uncertain、模式冲突及技术未完成都不阻断提交。
- 插件规则目录只有 LOCAL-USER-001 安全约束覆盖和 LOCAL-USER-002 历史授权／身份声明组合绕过两条窄模式。
- 已有本地确定性测试及此前一次真实 EdgeOne Jev 连通性验证；不能据此声称真实分类质量、规则完备或真实 OpenCode 宿主防护已验证。本轮尚未重新运行测试或调用外部模型。

## 沿用的已确认边界

- 记忆投毒领域定义不限内容来源；当前完善对象是 session.prompt。
- 不把正常任务、偏好和先前要求调整直接判为攻击；依据不足不能视为安全。
- 仅用 Jev 原生 Choice，保留独立文本引擎与宿主适配层分离。
- 会话历史、附件、技能和持久记忆文件仍不在实现范围内，除非用户明确扩大。
- 阈值、检测超时、正则时限、重试和完整 ATR 兼容不因“完善”自动加入。
- 本轮选择恶意正文整条固定替换，不实施拒绝提交；现有“不修改正文”的实现目标已明确变更，代码尚未修改。

## 第一轮决定

1. 用户选择对恶意文本进行改写，不采用上一轮建议的拒绝提交。具体改写粒度、保留内容和实现方法尚未确定。该决定变更旧的“保持正文不变”约定，但不自动授权新增生成式改写模型。
2. 用户要求继续参考 agent-threat-rules，尽量覆盖多种来源。“来源”是攻击场景／参考规则来源，还是新增实际内容入口，尚需明确，不据此自行扩大到其他 hook、附件或历史读取。
3. 用户接受将真实宿主集成验证及单独显式的真实 Jev 样本评测纳入完成标准。具体样本、调用数量和验收指标待后续确定；当前不启动外部评测。

## 第二轮决定

1. 用户确认采用整条替换。替代内容为固定中性提示，不生成局部修复文本，也不新增生成式改写模型。Jev Choice 不提供恶意片段定位，规则匹配区间不能作为全部恶意内容范围。
2. 用户澄清仅限定当前 session.prompt hook，只考虑用户输入，再确定适合该输入的关键词和正则。不增加其他检测入口，不搬入要求读取工具、技能或历史的规则。
3. “输入替换”术语已记录到 GLOSSARY；整条替换取舍见 ADR-0002。现有运行时仍是原实现，不能将设计决定描述为已交付能力。

## 第三轮决定

1. 用户接受保留现有汇总：关键词／正则作为风险证据，所有有效未超限正文均调用一次 Jev，最终 malicious 才替换；规则命中而 Jev benign 的冲突保持 uncertain，不直接替换。
2. 用户接受 uncertain（语义模糊或规则冲突）及技术未完成（服务失败、无效响应、超限、初始化不可用）保留正文并明确告警。它们仍可进入后续模型处理，这是可用性取舍，不等于检查通过或安全。
3. 用户接受首批六类：指令覆盖、角色／优先级伪造、恶意后续行为设定、授权捏造、结构化包装注入、可见编码混淆迹象。验收语言为中文、英文与混合输入；每类配正反样本，单个触发词不直接定性。不新增自动解码流程。

## 第四轮决定

1. 用户接受为已连接的 OpenCode TUI 增加可见通知，并在无界面或断线时保留结构化日志。需要独立 TUI 入口和 RPC 转发，不把服务器 prompt metadata 当成自动可见通知；不建设告警历史或断线补投系统。
2. 用户接受首轮真实评测采用 60 条独立标注样本（六类各 5 条攻击、5 条正常），每条运行 3 轮，合计 180 次 Jev 请求。准备样本后按已确认范围执行，本次讨论不启动调用。
3. 用户接受正常样本每轮 0 次误替换、攻击样本每轮至少 90% 明确 malicious 并触发替换、无技术未完成，并单列 uncertain、误告警及耗时；真实宿主验证实际持久化和模型接收内容。攻击样本 uncertain 不算检出，正常样本保留原文但 uncertain 不能写成正确 benign。

## 已核对的宿主事实

- 当前官方 prompt hook 提供可变草稿，改写后内容成为规范持久化用户输入，不只是影响一次模型请求。修改正文时需修正或移除不再匹配的附件 mention 偏移。
- hook 在附件和技能解析前运行，后续注册的 hook 可继续修改输入；没有类型化拒绝 API，不把工具前置异常语义套用到这里。
- 来源：[OpenCode v2 prompt admission](https://opencode.ai/v2/docs/build/plugins/#prompt-admission)。事实核查不等于真实宿主行为已验证。
- 当前服务器插件 Context 无直接 UI／toast API。原生 toast 属于独立 TUI Context，可经共享 RPC 事件从服务器转发；RPC 事件只实时投递，不能保证断线期间送达。来源：[CLI 提示接口](https://opencode.ai/v2/docs/build/plugins/cli/#dialogs-and-toasts)、[插件 RPC](https://opencode.ai/v2/docs/build/plugins/rpc/)。
- 本机 npm shim 指向 @opencode/cli 的 opencode.exe，对应已安装包声明版本为 2.0.32；二进制自报版本及实际运行尚未取得。版本命令受日志写入权限限制，本轮未升级、安装或启动宿主会话，不能以包版本或插件 SDK 2.1.0 代替集成验证。
