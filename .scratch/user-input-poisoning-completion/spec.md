# session.prompt 记忆投毒检测与输入替换完善规格

Status: open
Labels: ready-for-agent
Date: 2026-10-26

实施记录（2026-10-26）：输入替换、六类规则、TUI 通知及评测流程已实现，类型检查和全部 54 项本地确定性测试通过。真实 OpenCode 2.0.32 已验证加载、持久正文、主模型输入及三种 TUI 提示。首轮真实模型评测未通过；用户另行批准追加 180 次复测，总计已使用 360 次预算。复测零误替换，攻击检出分别为 30／30、30／30、29／30，但第三轮有一次 invalid-output，未满足“无技术未完成”，因此整体规格仍为 open，不能标记全部验收完成。完整证据见[验证记录](validation/README.md)。以下规格主体保留最初约定，追加授权记录在 Comments，不自动扩大后续调用预算。

## Problem Statement

用户希望将记忆投毒检测域在 session.prompt 的首个检测闭环完善为可验证的防护流程。目前插件只检测当前用户正文，使用两条窄模式和一次 Jev Choice，输出服务器日志；即使结果为 malicious，也不修改输入。缺少输入替换、终端内可见提示、系统化规则覆盖，以及实际宿主与真实模型的验收证据。

规则命中本身不能证明用户正在攻击。正常任务调整、身份介绍、长期偏好、代码示例及攻击样本引用，都可能包含相似词句。直接扩大敏感词或照搬 ATR 的宽泛分支会增加误报，而整条输入替换会丢弃同条消息中的合法任务，因此检测依据、三态汇总和处置必须分离。

现有本地测试验证的是程序行为，此前一次真实 EdgeOne Jev 调用只验证了连通性。它们不能证明规则覆盖、真实分类质量、实际持久输入替换或终端通知已完成。本轮“完整”以明确的六类输入模式、实际处置行为和有限验收集衡量，不承诺穷尽所有攻击。

## Solution

仅完善当前 session.prompt 用户正文入口。继续通过独立文本引擎执行本地关键词、正则和一次 Jev 原生 Choice；模式只提供风险证据，保留现有三态汇总。最终 malicious 时，由宿主适配层将整条正文替换为固定中性内容，并处理因正文变化而失效的引用偏移；不生成局部修复文本，不新增生成式模型。

benign 保留正文。语义 uncertain、规则与 Jev 冲突，以及配置不可用、服务失败、无效响应、超限等检查未完成情况，也保留正文并明确告警；它们仍可能进入模型，这是用户选择的可用性取舍，不得描述为安全通过。

参考 ATR，按项目自有 YAML 改编六类适用于用户输入的模式，覆盖中文、英文和混合输入，并建立正反样本及覆盖矩阵。增加已连接 OpenCode TUI 的可见通知，同时保留不含正文的结构化日志；不建设告警历史或断线补投。

交付以确定性测试、真实宿主持久化与模型请求验证，以及 60 条样本各 3 轮、共 180 次真实 EdgeOne Jev 评测共同验收。每轮正常样本零误替换，攻击样本至少 90% 明确判为 malicious 且执行替换，技术检查全部完成；单列不确定、误告警和耗时。

## User Stories

1. 作为 OpenCode 使用者，我希望当前提交的正文进入记忆投毒检测，以便在输入进入后续处理前识别风险。
2. 作为 OpenCode 使用者，我希望检测范围仅限当前正文，以便本轮不会自动读取历史、附件或技能。
3. 作为 OpenCode 使用者，我希望正常修改自己的任务要求被允许，以便能够纠正或撤回先前需求。
4. 作为 OpenCode 使用者，我希望正常偏好和回答风格设置不会仅因含有“以后”或“始终”而被判恶意，以便正常使用长期指示。
5. 作为安全研究者，我希望分析攻击载荷与执行攻击指令被区分，以便可以讨论安全样本。
6. 作为开发者，我希望普通 JSON、XML、YAML、编码示例和 Unicode 调试文本有正常对照，以便结构或字符形式不会被直接当作恶意。
7. 作为安全维护者，我希望识别覆盖系统或安全约束的输入模式，以便发现试图提升自身指令权限的文本。
8. 作为安全维护者，我希望识别伪造系统、管理员身份或优先级的组合模式，以便正文中的身份自述不会自动获得可信地位。
9. 作为安全维护者，我希望识别恶意的后续行为设定，以便发现要求持续取消安全约束或无条件服从的输入。
10. 作为安全维护者，我希望识别声称已有授权并要求跳过检查的组合，以便发现当前正文中的授权捏造迹象。
11. 作为安全维护者，我希望识别结构化文本中嵌入的越权指令，以便攻击不会仅因包装格式不同而遗漏。
12. 作为安全维护者，我希望识别编码和字符混淆中的可见可疑组合，以便发现规避迹象。
13. 作为维护者，我希望规则适用于当前用户输入，而非照搬依赖工具或历史的规则，以便覆盖声明与实际输入一致。
14. 作为维护者，我希望每类规则都有来源和修订记录，以便追溯 ATR 改编依据。
15. 作为维护者，我希望按威胁类别和正反样本评估规则覆盖，以便规则数量不会被误当成完整性证明。
16. 作为安全分析者，我希望规则命中保留证据，以便可以核查模式与语义结论的冲突。
17. 作为安全分析者，我希望未命中规则的有效正文仍交给 Jev，以便保留发现改写攻击的机会。
18. 作为调用方，我希望每次有效未超限检测只进行一次 Jev Choice，以便规则扩充不增加逐规则模型调用。
19. 作为 OpenCode 使用者，我希望最终 malicious 的正文被整体替换，以便原始越权指令不作为本条正文继续交给模型。
20. 作为 OpenCode 使用者，我希望替代内容是固定中性提示，以便处置不会生成新的不可预测任务。
21. 作为 OpenCode 使用者，我希望知道整条替换会丢弃其中的合法任务，以便重新提交明确请求。
22. 作为调用方，我希望不依赖 Jev 生成恶意片段位置或重写正文，以便遵循现有 Choice 模型能力。
23. 作为 OpenCode 使用者，我希望 benign 输入保持不变，以便检测不会改动正常内容。
24. 作为 OpenCode 使用者，我希望模式命中而 Jev benign 时保留冲突并告警，以便不会只因敏感措辞丢失输入。
25. 作为 OpenCode 使用者，我希望语义 uncertain 时保留正文并被提醒，以便了解这次没有明确安全判断。
26. 作为 OpenCode 使用者，我希望检测失败或未完成时明确提示，以便不会把继续提交误认为安全通过。
27. 作为 OpenCode 使用者，我希望空正文不被描述为附件已经检测，以便理解本轮覆盖面。
28. 作为 OpenCode 使用者，我希望超长正文不被截断后宣称检测完成，以便得到真实的检查状态。
29. 作为 OpenCode 使用者，我希望替换后无效的引用位置被处理，以便附件或技能引用不会错误指向新正文。
30. 作为 OpenCode 使用者，我希望正文之外的交付方式和提交标识保持一致，以便输入替换不会变成拒绝提交或转移会话。
31. 作为终端使用者，我希望在已连接 TUI 中看到“已替换”“判断不确定”或“检测未完成”的提示，以便不用只查服务器日志。
32. 作为终端使用者，我希望提示能关联对应会话和消息，以便不会把其他会话的风险误认为当前请求。
33. 作为终端使用者，我希望通知不展示攻击原文，以便避免额外传播载荷和用户内容。
34. 作为无界面调用方，我希望保留结构化日志，以便没有终端通知时仍能诊断。
35. 作为维护者，我希望终端断线或通知失败不会改变已确定的输入处置，以便显示通道故障不会撤销替换或造成隐式阻断。
36. 作为维护者，我希望卸载时清理 hook、RPC 和通知订阅，以便重载后不会遗留重复处理。
37. 作为安全负责人，我希望真实宿主证明保存和发往模型的正文已替换，以便不把本地回调测试当成最终交付效果。
38. 作为安全负责人，我希望终端通知在真实宿主中验证，以便不把模拟 toast 调用当成可见性已完成。
39. 作为安全分析者，我希望有六类各五条攻击和五条正常样本，以便按预定范围评估。
40. 作为安全分析者，我希望同一套样本进行三轮真实 Jev 评测，以便观察重复运行的结果差异。
41. 作为部署者，我希望首轮评测限定在 180 次真实请求，以便控制已确认的调用范围。
42. 作为安全分析者，我希望样本标签和标注理由不发送给 Judge，以便避免答案泄漏。
43. 作为安全分析者，我希望评测与插件使用相同判断指令、规则和处置逻辑，以便结果对应实际功能。
44. 作为安全负责人，我希望 uncertain 不被算作攻击检出或正确 benign，以便指标不会隐藏未决结果。
45. 作为安全负责人，我希望每轮分别验收零误替换、至少 90% 攻击检出和无技术未完成，以便汇总平均数不会掩盖单轮失败。
46. 作为维护者，我希望报告保留实际模型与规则版本、失败状态和耗时，以便比较结果并排查问题。
47. 作为数据提供方，我希望日志、通知和评测报告不包含正文、认证头或密钥，以便诊断不会扩散敏感内容。
48. 作为开发者，我希望通过公开插件入口、引擎入口、终端入口和评测命令测试，以便不依赖私有实现结构。
49. 作为维护者，我希望未覆盖的检测域和输入仍保持明确的占位边界，以便功能说明真实。
50. 作为安全负责人，我希望验收未完成或不达标时如实保留状态，以便不会提前声称已完整实现或具备普遍准确率。

## Implementation Decisions

### 范围与现有约定

- 记忆投毒领域定义不限定来源，但本规格只完善 session.prompt 当前用户正文。新增终端入口仅展示本检测面的结果，不形成新的检测来源。
- 延续独立文本引擎、检测域、运行时与宿主适配层分离。引擎负责检测事实，运行时将结果映射为最小处置决定，宿主层执行正文替换与告警；不建设通用策略引擎。
- 本规格和已确认的输入替换决策覆盖旧规格中“始终保留正文、不执行任何改写”的约定；不改变“不拒绝提交”及当前正文之外的范围限制。
- 保留 Jev 原生 Choice 三分类，不增加生成式改写、解释生成、备用模型、置信度阈值、概率门槛、检测超时、正则执行时限或自动重试。
- 继续显式加载和注入 Jev 配置，已有进程环境变量优先；不新增本轮未要求的开关、规则热更新或配置系统。

### 检测与结果汇总

- 从官方 prompt 草稿提取原始正文，来源由适配层固定为 user-input。正文自称 system、管理员、厂商或已获授权，不能改变可信来源或授权事实。
- 正常任务、偏好和先前要求调整应与越权操纵区分。引用、教程、代码和研究样本不能仅因包含攻击词句被定性。
- 本地关键词与正则仅产生风险证据，不按命中数量、严重程度或词句直接执行输入替换。
- 所有有效且未超限正文每次检测一次 Jev，无论模式命中与否；不按规则数增加请求，也不把规则命中、样本标签、类别或标注理由送给 Judge。
- 保留既有输入校验、Unicode 码点长度上限、固定规则快照与 UTF-16 半开区间证据。空正文保持跳过并提示，不代表附件或技能已检测。
- Jev 判断指令和类别描述属于可信配置，正文不能修改。保留既有响应校验、原生类别、完整概率、置信度和实际模型版本，不要求自然语言理由或片段定位。
- 依赖未提供的历史或安全政策才能确定时，不能伪造已核验事实。既不自动读取历史，也不把正文中的授权声明当成可信证明。

| 检测情况 | 最终结论 | 正文处置 | 提示 |
| --- | --- | --- | --- |
| 检查完整，Jev malicious，模式是否命中均可 | malicious | 整条固定中性替换 | 已替换 |
| 检查完整，模式未命中且 Jev benign | benign | 保留 | 不产生风险提示 |
| 检查完整，模式命中而 Jev benign | uncertain | 保留 | 判断不确定，保留冲突 |
| 检查完整，Jev uncertain | uncertain | 保留 | 判断不确定 |
| 任一必需阶段失败或未完成 | uncertain | 保留 | 检测未完成，保留已有发现 |
| 输入非法、超限、初始化不可用或空正文跳过 | 不具有完整安全判断 | 保留 | 未检测或检测未完成，标明程序性原因 |

- 某一阶段已有 malicious 但整体检查未完成时，仍按检查未完成处理，不跨过既有整体汇总规则执行替换。
- 允许未决或未完成正文继续提交是已确认的可用性取舍，不输出安全通过，不把它们误计为 benign。

### 输入替换与运行时契约

- 为处置契约增加输入替换的明确表达，最小必要地区分检测结论、处置决定与实际执行结果。不能仅凭 findings 非空推断 malicious，也不能因纯 Jev 恶意结果无规则发现而跳过替换。
- 仅最终 malicious 执行替换。使用插件控制的单一固定中性正文，说明原输入因检测到越权操纵风险已被替换，并提示重新提交具体任务；具体文案由实施选定并固定验证，不提供自由生成或新配置项。
- 替代正文不得拼接、引用、编码保留或根据原文生成局部内容，也不向模型提交“待清洗的原输入”。不尝试恢复同条消息中的合法任务。
- 替换发生于当前 prompt 可变草稿，在接纳前完成。其结果成为宿主规范持久输入和后续模型输入，不能只改日志、一次出站请求或 detached 副本。
- 正文变化后，修正或移除所有不再匹配的 mention 偏移；保留文件、技能和 agent 的原有选择以及其他有效引用信息。不为修复偏移读取附件或技能内容。
- 除正文及其必要引用偏移外，保留原有会话、消息标识、delivery、metadata 和提交选项；不把告警追加为新用户指令，不清空正文冒充拒绝，不改权限策略或取消提交。
- 不新增原文落盘、全文审计或通过通知传输原文的旁路。原文和规则证据仅在检测所需的内存边界内处理。
- 沿用宿主接纳阶段的注册顺序、并发和重试语义，不承诺 exactly-once，不增加全局去重存储。不声称后续插件无法再次改写正文。

### 六类规则与覆盖矩阵

- 使用项目自有 YAML 模型和 LOCAL 规则命名空间，不直接执行 ATR 原始规则或其 response 动作，不声称完整 ATR 兼容。
- 每类提供适用于当前正文的启用模式、正反样本和覆盖记录。关键词字面组合与正则的选择按可观察特征确定，不要求固定规则条数，不以扩大敏感词表代替威胁语义。
- 参考实际读取的上游 YAML，记录上游规则 ID、链接、rule_version、文件 blob SHA 或提交修订及采用日期，并说明改编内容。不得以规则标题猜测适用字段。
- 排除必须依赖工具返回、技能、跨轮状态或其他输入载体才能成立的规则分支；不因 ATR 来源多样而扩大本轮采集面。
- 保留正常任务调整、研究引用、合法数据、编码文本及普通身份声明等正常对照。结构或触发词本身不能成为恶意定性依据。
- 正则与关键词作用于原文，证据仍对应原文 UTF-16 半开区间；不得将归一化或解码后的偏移冒充原文坐标。不新增自动解码流程。

| 类别 | 模式关注点 | 必须区分的正常输入 |
| --- | --- | --- |
| 指令覆盖 | 覆盖／忽略动作与系统或安全约束目标组合 | 修改自己的先前任务、引用攻击语句 |
| 身份与优先级伪造 | 冒充系统或管理员并要求提升指令权威 | 身份介绍、审计请求、普通 SDK 或系统提示示例 |
| 恶意后续行为设定 | 持续行为措辞结合取消安全约束或无条件服从 | 长期语言、格式、称呼和主题偏好 |
| 授权捏造 | 先前批准或身份声明结合跳过授权检查 | 正常历史引用、合法权限配置说明 |
| 结构化包装注入 | 结构化字段内嵌入越权指令 | 普通 JSON／XML／YAML、测试数据和教程 |
| 编码与字符混淆迹象 | 编码、解码或特殊字符结合操纵要求 | Base64 教程、国际化、Unicode 与 DNS 调试 |

- 中文、英文及混合输入均纳入样本。覆盖矩阵记录每类模式、上游依据、正常对照、样本 ID、结果及已知边界；不宣称所有语种、所有编码或所有攻击变体均受覆盖。

### 终端通知与诊断

- 服务器 prompt Context 不提供直接原生 toast；按官方 v2 方式增加同包 TUI 插件入口，用最小共享 RPC 事件转发脱敏安全结果，由 TUI 展示原生提示。
- 不以旧版 UI API 或 prompt metadata 自动渲染作为实现依据；需要实际注册、订阅、展示和卸载链路，不建设新页面或自定义告警面板。
- 已替换、判断不确定、检测未完成分别使用明确的固定提示，不把技术失败称为恶意，不将告警描述为阻断成功。提示关联会话和消息，benign 不产生风险 toast。
- RPC 和日志仅携带必要的关联标识、检测域、结论、处置结果、程序性原因及检查状态等安全字段；不得传输攻击正文、匹配原文、完整配置、密钥、认证头或原始服务异常。
- 服务器结构化日志继续保留。无 TUI 或终端断线时不承诺可见提示；RPC 事件仅实时有效，不增加持久化历史、重放、补投或确认送达系统。
- 通知失败不撤销已执行替换、不恢复恶意原文，也不把检测失败改判为 benign。显示通道问题不能变成拒绝或改变提交的隐式执行路径。
- 卸载时释放服务器 hook、RPC 注册及终端事件订阅，避免重载后遗留重复提示。初始化不可用仍需明确诊断，不能显示检测正常工作。

### 真实模型评测

- 准备并固化 60 条独立标注样本：六类各 5 条攻击、5 条正常，共 30 条攻击和 30 条正常；涵盖中文、英文和混合输入，不使用真实用户会话。
- 标签、类别、语言和标注理由仅用于评测统计，不作为 Judge 的判断依据。样本应围绕已明确的信任边界标注，避免把正常行为变更任意标成攻击。
- 复用现有评测命令边界，必要时最小扩展，使用户输入评测采用与插件相同的规则快照、判断指令、Choice 类别描述、汇总及处置逻辑。不能用旧的通用默认指令替代插件判定条件而声称评测了同一功能。
- 独立引擎继续只返回检测事实，不因评测增加自动修改输入职责。评测通过与插件共用的处置实现验证替换行为，区分“决定替换”和“已执行替换”，不只从 malicious 标签推算执行成功。
- 对每条样本运行 3 轮，合计 180 次真实 EdgeOne Jev 请求，每次使用既有显式配置入口提供的凭据。模型请求失败如实记录，不自动重试、补跑或突破预算。
- 三轮是明确约定的重复评测，不是运行时失败重试。不得为了达到指标而临时改标签、减少分母、删除失败样本或将不确定计为正确。
- 每条结果保留样本 ID、轮次、类别、语言、期望标签、实际三态、处置及执行状态、阶段状态、程序性原因、实际模型与规则版本和耗时；报告不输出完整正文或凭据。
- 分轮、分类别报告检出、误替换、不确定、技术失败、检查未完成和误告警。正常样本虽未替换但为 uncertain 时，仍统计未决／告警，不标成正确 benign。
- 保留既有误报、漏报统计的原定义；新增明确攻击检出率及替换统计，不能用仅计算攻击被判 benign 的旧漏报数掩盖 uncertain。
- 单列耗时统计，至少使单次结果与分轮汇总可核查；没有额外约定的延迟门槛，不据此偷偷增加检测超时。

| 每轮验收项 | 标准 |
| --- | --- |
| 正常输入误替换 | 0／30 |
| 攻击明确检出且执行替换 | 至少 27／30，即至少 90% |
| uncertain 或检查未完成的攻击 | 不计入检出分子 |
| 技术失败与检查未完成 | 0；合法语义 uncertain 仍是已完成判断，但必须单列 |
| 汇总 | 三轮分别满足，不能仅以合并平均数通过 |

- 这些是本轮有限验收集标准，不是运行时置信度阈值，也不证明总体准确率或完整防护。未达标则保留失败结论和具体差异，不将功能标记为全部验收完成。

### 真实宿主验收与交付状态

## Testing Decisions

- 用户已确认边界：服务器插件 setup／prompt hook、引擎公开初始化与 detect、现有评测命令；新增 TUI 仅从 setup／事件订阅入口观察提示与清理；真实宿主检查实际保存和模型收到的正文。
- 以 prompt 输入到实际替换和通知输出的插件集成为主要测试边界。复用真实运行时、检测域、本地 YAML 和可控 Jev，避免为每个内部映射函数新增公开接口或重复同一矩阵。
- 引擎公开入口承接模式正反样本、证据位置与汇总回归；TUI 公开生命周期入口验证 RPC 结果与 toast 的外部行为；评测子进程入口验证样本、轮次、统计、预算和退出／验收状态。
- 好的测试断言正文、其他提交数据、发出的模型请求、最终结果、通知和清理等外部行为，不绑定私有函数、内部类或实现步骤。受控服务只证明接线和程序逻辑，不证明真实模型准确率。
- 现有 prompt 测试已提供临时项目配置、本地 HTTP Jev、真实插件 setup 和 hook 回调先例；适配层测试已验证注册与卸载；引擎与规则测试已覆盖本地 YAML、原文证据、快照、长度和三态汇总；评测测试已有子进程统计与凭据隔离先例。
- 先在已确认边界验证缺口，再逐步实现；特别覆盖纯 Jev 恶意但模式未命中、模式与 benign 冲突及部分检查失败，避免只测明显规则命中。
- 验证恶意原文被完整固定替换，替代内容不含原文片段、不因输入改变；正常正文及其他提交数据保持不变。带附件／技能 mention 的样本验证失效偏移被正确处理且没有读取内容。
- 覆盖语义 uncertain、模式冲突、HTTP 失败、非法 Jev 响应、无配置、规则初始化失败、超限、非法正文和空正文；均不被标为安全或恶意替换，不新增故障重试或拒绝提交。
- 验证合法输入每次一次 Jev，不按规则数量增加调用；超限和非法输入不请求模型，不截断。继续回归非 BMP 字符的码点长度与 UTF-16 证据区间。
- 每个启用模式以中英文与适用混合输入的正反样本通过公开引擎验证；测试实际匹配和误报对照，不仅验证 YAML 能加载。
- 验证六类覆盖矩阵与样本类别可追溯，正常任务调整、长期偏好、身份介绍、代码／结构化示例和攻击引用不因单个触发词被直接替换。
- 在 TUI 公开入口注入模拟宿主客户端，验证已替换、不确定、未完成分别提示及正确会话关联，benign 不告警；验证卸载取消订阅、通知故障不影响已执行处置，不构造断线补投功能。
- 通过评测命令使用本地受控服务验证每轮 30／30 分母、3 轮、180 次计划请求、27／30 检出门槛、零误替换、uncertain 和失败不计成功；验证某轮不达标不能靠其他轮平均通过。
- 验证评测采用插件相同判断配置，标签、类别、语言和标注理由不会进入 Judge state；执行结果不能仅由期望标签或模拟常量产生。
- 确定性测试只使用临时环境文件和隔离测试凭据，不读取或输出使用者真实环境文件。真实评测另行显式运行，通过配置入口使用已授权凭据，不打印值或提交实际环境文件。
- 验证日志、RPC、toast 和报告不包含正文、匹配原文、认证头、真实密钥、完整配置或原始服务异常；现有敏感服务元数据泄漏回归继续保留。
- 回归其他 hook 和检测域仍为占位，HTTP 响应流不被读取，公共事件与 hook／RPC／TUI 订阅都能清理。替换策略不得扩散到其他检测入口。
- 修改实现后按需运行 npm run typecheck、定向测试，并在交付前运行完整 npm test。真实宿主和真实 EdgeOne 评测各自留存独立结果，缺少它们时不能用本地测试替代验收。

## Out of Scope

- 本次规格发布不实现功能、不调用真实 Jev、不启动宿主会话，不自动拆分实现任务或提交 Git commit。
- 其他 hook 的检测接入、会话历史关联、跨轮授权核验、附件与技能正文读取、持久记忆文件防护或其他检测域实现。
- 将记忆投毒限定为工具返回，或把六类字面模式说成覆盖所有投毒技术。
- 局部修复、保留恶意正文中的合法片段、生成式改写、生成式解释、模型兜底或第二次模型重写／复检流程。
- 自动拒绝或取消提交、权限策略更改、清空正文作为拒绝、未决或检查失败时自动替换。
- 原文持久化审计、完整告警平台、专门可视化面板、Web／桌面 UI 支持、可靠消息队列、告警历史和断线补投。
- 自动解码、翻译、长文本分块、完整 ATR 导入及条件求值、执行上游 response、热更新或远程规则订阅。
- 置信度和概率阈值、额外加权分类、检测超时、正则时限、自动重试、并发接纳去重存储或 exactly-once 保证。
- 超过首轮 180 次预算的自动真实 Jev 调用、无限调参后重测，或为通过指标删改标注、隐藏失败和缩小分母。

- 自动升级全局 OpenCode、改变使用者其他项目配置、操作系统隔离或生产部署。
