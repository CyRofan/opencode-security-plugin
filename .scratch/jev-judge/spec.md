# Jev 原生语义裁判与环境配置规格

Status: ready-for-agent

## Problem Statement

当前文本检测引擎使用生成式 Chat Completions Judge，要求模型生成结论、非空理由及可核验的原文片段。使用者已明确改用 TypeSafe Jev，且不再需要原有生成式 Judge。

Jev 以状态和类型化问题返回分类、概率分布及置信度，不提供当前契约要求的生成式理由和原文证据。仅替换模型名称不能完成接入，继续强制这些字段还会将合法响应误判为失败。模型服务配置也需要通过本地环境文件管理，避免凭据进入代码、版本记录或错误输出。

## Solution

将 Judge 层收敛为 Jev 原生 Choice 三分类，直接通过 HTTP 请求接入。正文、来源和可选任务上下文组成 state；独立检测问题及类别描述定义判断目标。每条有效文本调用一次 Jev，保留其分类、完整概率分布、置信度及实际模型版本，直接将分类映射为既有三态结论，不增加置信度阈值。

保留本地 YAML、关键词和正则、规则证据及既有汇总语义，移除生成式 Judge 的适配器、输出要求和对外使用入口。配置入口加载本地环境文件并校验配置后注入适配器，引擎不自行扫描或读取配置文件。更新已有评测命令及说明，不实现 hook 自动接入或阻断。

## User Stories

1. 作为引擎调用方，我希望只接入 Jev 作为语义裁判，以便无需维护不再需要的生成式 Judge。
2. 作为引擎调用方，我希望继续通过原有文本检测入口提交正文、来源和可选上下文，以便复用现有集成边界。
3. 作为安全维护者，我希望 Jev 区分恶意操纵、正常内容和不确定内容，以便识别工具返回文本的投毒风险。
4. 作为安全维护者，我希望类别描述明确区分实际攻击与教程引用，以便延续既定检测目标。
5. 作为引擎调用方，我希望每条有效文本只请求一次 Jev，以便不随规则条数增加模型请求。
6. 作为安全分析者，我希望规则未命中时仍请求 Jev，以便检测改写攻击。
7. 作为安全分析者，我希望 Jev 独立于规则命中结果判断，以便保留模式与语义检测的独立信号。
8. 作为安全分析者，我希望结果保留原生分类、完整概率分布和置信度，以便后续分析判定边界。
9. 作为安全分析者，我希望记录服务实际返回的模型版本，以便区分配置中的模型别名和真实执行版本。
10. 作为引擎调用方，我希望直接映射 Jev 类别而不增加置信度阈值，以便先获得可评测的原始分类行为。
11. 作为安全分析者，我希望低置信度但合法的分类仍正常完成，以便不把尚未约定的阈值偷偷加入判定。
12. 作为引擎调用方，我希望 Jev 不返回自由文本理由或证据时仍视为有效响应，以便遵循该模型实际能力。
13. 作为安全分析者，我希望关键词和正则仍保留原文证据，以便独立核查模式命中。
14. 作为引擎调用方，我希望网络失败与非法 Jev 响应区别于正常的不确定类别，以便识别技术故障。
15. 作为处置层调用方，我希望继续收到检测事实而非由引擎自行阻断，以便保留既有职责划分。
16. 作为安全分析者，我希望正则未命中而 Jev 判断有风险时整体有风险，以便不否定语义攻击检测。
17. 作为安全分析者，我希望规则命中而 Jev 判断正常时保留冲突，以便不静默丢弃规则发现。
18. 作为部署者，我希望通过本地环境文件提供 API Key、完整服务 URL 和模型名称，以便不在代码中硬编码配置。
19. 作为部署者，我希望已有进程环境变量优先于本地环境文件，以便兼容部署环境注入配置。
20. 作为新维护者，我希望获得仅含变量名及占位值的配置示例，以便理解必需配置且不接触真实凭据。
21. 作为仓库维护者，我希望本地环境文件及其变体被 Git 忽略而配置示例可追踪，以便避免误提交凭据。
22. 作为部署者，我希望缺少配置时仅看到缺失变量名，以便修正配置且不泄露现有值。
23. 作为数据提供方，我希望错误、日志和评测输出不含认证头或完整配置，以便避免凭据通过诊断泄露。
24. 作为开发者，我希望用可控 Jev HTTP 服务从公开入口测试，以便日常测试不依赖真实凭据、外部服务或模型随机性。
25. 作为安全维护者，我希望已有评测命令报告 Jev 分类、概率、置信度及实际模型版本，以便后续研究阈值而非先假定阈值有效。
26. 作为开发者，我希望保留既定无检测超时、无正则时限和无自动重试约定，以便迁移不改变已确认的运行策略。
27. 作为维护者，我希望所有当前使用示例和测试都迁移到 Jev，以便不会继续引导调用已经删除的生成式适配器。

## Implementation Decisions

### 范围与迁移边界

- 仅保留 Jev 语义裁判。删除原有 Chat Completions 适配器及其公开导出，不保留生成式兼容模式、多提供者切换或故障兜底模型。
- 调整 Judge 契约、响应校验、评测配置与输出以及当前文档；清理因本次替换产生的孤立类型、测试和引用。
- 本地 YAML 加载与校验、固定快照及版本、关键词任一或全部匹配、正则匹配和原文证据继续使用现有实现与语义。
- 继续使用独立文本输入，语义裁判不处理原始 OpenCode 安全事件。首个检测目标仍是工具返回内容污染上下文，不包括持久记忆文件。
- 继承原文本引擎规格中未被本次替换的行为。本次规格覆盖旧规格中的生成式模型请求、生成式输出及旧模型环境变量约定；旧规格作为历史记录保留，不要求同时实现两种相互冲突的方案。

### Jev 请求契约

- 使用 TypeSafe 官方 Jev HTTP API 的 state、model、questions 原生结构，不套用 Chat Completions 的消息及生成式 JSON 输出协议。
- state 包含待检正文、调用方提供的来源和可选任务上下文。不自动获取完整会话，不把关键词或正则命中结果、评测标签或标注理由放入 state。
- 每个请求先只包含一个投毒检测 Choice 问题，类型为 choice。判断问题及类别描述属于可信检测配置，不从待检正文中读取或修改。
- 三个类别固定为 malicious（试图改变 Agent 的任务、权限或行为）、benign（正常内容及单纯攻击引用）、uncertain（信息不足或语义模糊）。类别描述应围绕此边界，不能仅根据是否出现攻击词句定义类别。
- 对已初始化引擎中的有效、未超限文本，每次检测调用一次 Jev。规则命中和未命中均不跳过语义判断，不按规则条数增加请求。
- 默认采用直接 HTTP 请求，继续不设置应用层检测超时、不自动重试，不引入 SDK 的默认重试行为。远端服务、网络或操作系统仍可能自行断开连接。

### 原生结果与校验

- 成功结果保留 Jev 选择的类别、三个类别的完整 probabilities、confidence，以及服务实际返回的 model。配置模型别名与实际响应模型版本应可区分，不用请求中的别名伪造实际版本。
- 不再要求模型返回自然语言 reason 或原文 evidence，不通过另一次生成式调用补充解释，不把规则证据伪装为 Jev 的原文定位。
- 引擎整体的程序性汇总原因和技术错误码可以继续保留，但不得称为模型推理理由。关键词和正则的证据结构与原文位置约定不变。
- 校验响应中的目标问题存在且类型正确，类别属于约定集合，概率及置信度为有效数值且在合法范围内。完整性及概率分布的数值校验应遵循官方 Choice 契约，实施时明确浮点容差，不把数值合法性检查当作业务风险阈值。
- 合法 Choice 响应计为 completed；正常选择 uncertain 也属于完成，不属于技术失败。缺少生成式理由或原文证据不构成失败。
- 网络或 HTTP 服务异常标记 failed 及服务错误；缺失问题答案、未知类别、缺失概率、非法数值或不合法响应结构标记 failed 及无效输出。不据残缺响应推断未发现风险。
- 失败状态与原生 uncertain 类别分开记录，继续保留其他阶段已产生的规则发现。

### 分类映射与汇总

- 直接将 malicious、benign、uncertain 映射为有风险、未发现风险、不确定。
- 首版不配置或执行置信度阈值，不因 confidence 低自动改为 uncertain，不设置概率门槛或新增加权策略。
- confidence 与某一类别的概率分别保存，不将 confidence 重新标记为攻击概率。概率及置信度用于观察和后续评测，不改变本轮决策逻辑。

| 条件 | 整体结论 |
| --- | --- |
| 任一必需阶段失败或未完成 | 不确定，并保留已有发现 |
| 检查完整，Jev 选择 malicious，无论模式规则是否命中及置信度高低 | 有风险 |
| 检查完整，规则命中但 Jev 选择 benign | 不确定，保留规则与分类冲突 |
| 检查完整，Jev 选择 uncertain | 不确定 |
| 检查完整，规则未命中且 Jev 选择 benign | 未发现风险 |

### 环境配置与凭据保护

- 使用 JEV_API_KEY、JEV_API_URL、JEV_MODEL 三个显式配置项。URL 是完整 Jev API 地址，模型由使用者配置，不在代码中硬编码真实凭据，也不自动依赖旧生成式模型配置。
- 本地实际值放入 .env；提供 .env.example，仅包含变量名和明显占位值，不能包含有效凭据。
- Git 忽略 .env 及本地变体，明确保留 .env.example 可追踪。必须验证忽略规则，不仅依靠使用说明提醒。
- 配置入口显式加载环境文件，再校验必需项并构造和注入 Jev 适配器；引擎核心不扫描磁盘寻找配置，不在导入时隐式读取环境文件或发送请求。
- 已有进程环境变量优先于环境文件的同名配置，不通过加载本地文件覆盖部署时注入的值。
- 缺失配置时提示缺失变量名，不能回显其他配置值；配置非法时同样不回显敏感值或完整配置。
- 日志、异常、测试快照和评测报告不得包含 API Key、Authorization 请求头、实际环境文件正文或完整配置对象。不得通过捕获原始 HTTP 错误而把认证信息带到公开结果中。
- 不创建或提交含真实值的配置文件，不要求提交凭据才能运行确定性测试。配置加载的具体实现由实施选择，必须满足优先级和现有 Node.js 运行方式。

### 评测与文档

- 已有评测命令改为 Jev 环境配置和原生响应，继续重复运行及统计误报、漏报、不确定、技术失败和未完成检查。
- 评测中记录请求模型标识及实际模型版本、规则快照版本、每次成功判断的类别、概率分布、置信度及耗时，便于后续分析，不记录凭据、完整配置或待检正文。
- 保留原先的统计定义、分母和未完成报告语义，不把 uncertain 或技术失败当作正确结果，不虚构质量阈值。
- 更新公开 API、配置示例、运行命令及能力边界说明；删除当前使用说明中引导调用已移除生成式 Judge 的内容，历史规格除外。
- 真实 Jev 质量评测需要使用者显式配置并单独执行；未执行时明确标记，不用替身响应声称真实模型准确率。

## Testing Decisions

- 沿用已建立的文本检测引擎公开入口及已有评测命令作为测试边界；本轮已向用户核对该边界，不新增仅为测试服务的内部公开方法。
- 引擎测试使用真实本地 YAML 及可控 Jev 依赖，模型适配测试使用可控 HTTP 传输或本地 HTTP 服务。仅验证外部行为，不断言内部私有函数或类结构。
- 现有引擎测试已覆盖规则快照、模式证据、长度上限及汇总，继续作为回归先例；现有模型测试和评测子进程测试可迁移为 Jev 请求和环境加载验证，不保留生成式模型特有断言。
- 验证 state、问题类型和三个类别正确；正文与来源上下文未混入可信判定条件；请求不含模式命中、评测标签或完整会话。
- 验证有效、未超限文本每次只请求一次 Jev，正常模式命中或未命中均不跳过，超限与非法输入不请求模型。
- 覆盖三个类别及完整概率和置信度保留，实际模型版本不被请求别名替代；以低置信度合法响应验证没有隐式阈值改判。
- 合法无 reason/evidence 的 Jev 响应应完成，不能触发原有生成式输出无效或证据无效错误。
- 覆盖服务异常、非成功 HTTP 状态、无法解析、缺失目标答案、未知类别及非法数值；失败不返回未发现风险，也不触发第二次模型请求。
- 回归完整汇总表，特别是模式未命中而 Jev 选择 malicious、规则与 benign 冲突、原生 uncertain、部分失败保留规则发现。
- 通过已有评测命令的子进程入口，使用临时环境文件和隔离进程环境验证本地加载、三个必需项、进程变量优先级、缺失或非法配置错误，以及输出不包含测试凭据和认证头。
- 验证实际环境文件及本地变体被 Git 忽略，而配置示例不被忽略且只有占位值；测试不得覆盖使用者现有环境文件，不读取或输出真实凭据。
- 验证评测报告中的分类、概率、置信度和实际模型版本，且未知或失败值不被伪造为成功概率；保持既有统计与退出状态语义。
- 日常测试不访问外部 Jev，不依赖真实 API Key。真实评测单独显式运行，不预设尚未约定的模型版本、准确率或置信度阈值。

## Out of Scope

- 本规格发布不包含功能实现、真实凭据配置或外部模型调用。
- 保留生成式 Judge、多模型兼容切换、自动兜底或新增解释生成模型。
- 自动置信度阈值、概率阈值、分数加权、基于不确定结果的模型升级。
- 同时使用 Choice、Noul 和 Score、多问题因果组合或逐规则模型调用。
- 新增检测超时、正则执行时限或自动重试。
- 修改 YAML 模式求值语义、完整 ATR 兼容、远程规则或热更新。
- hook 正文提取、流解析、四个域的自动接入、自动阻断、持久记忆文件防护或操作系统资源隔离。
- 凭据管理平台、自动获取密钥、密钥轮换、环境文件加密或秘密扫描服务。
- 修改历史规格以掩盖原有设计，或将外部真实 Jev 质量评测结果作为已完成事实。

## Further Notes

- 当前仓库仍使用生成式 Judge，且 Git 忽略配置尚未覆盖环境文件。本规格描述待实现行为，不表示 Jev 或环境配置已接入。
- “语义裁判”继续作为检测角色名称；Jev 是类型化决策模型，不据此要求其生成自然语言解释或原文证据。
- 官方契约参考：[TypeSafe Choice](https://docs.typesafe.ai/primitives/choice)、[官方快速开始](https://docs.typesafe.ai/introduction/quickstart)。Choice 的分类、概率与置信度是不同字段，不能用固定文本理由替代这些原生信号。
- [官方 SDK 说明](https://docs.typesafe.ai/sdk)涉及默认重试；本方案直接使用 HTTP，以保持已确认的不自动重试约定。
- 没有超时意味着耗时请求及正则可能持续阻塞调用方；本次不改变此前接受的取舍。
- 按本地 Markdown 任务跟踪约定发布，标记 ready-for-agent；本轮不自动拆分任务、修改实现或提交 Git commit。
