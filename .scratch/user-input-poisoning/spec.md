## Problem Statement

用户希望在 OpenCode v2 中复用现有文本检测引擎，对直接提交的消息正文识别记忆投毒风险。目前插件已注册用户输入 hook，但没有将正文提取后送入记忆投毒检测域和独立引擎，也没有把结果转换成可观察的告警。已有独立引擎通过本地 YAML、关键词、正则及 Jev 原生 Choice 返回三态结果，这不代表宿主中的用户输入已经受到检测。

项目此前把记忆投毒限定为工具返回内容污染上下文。用户已明确变更这一领域边界：工具返回污染只是其中一种，不能用单一内容来源限定整个记忆投毒领域。本轮只选择用户直接提交正文这一检测面，不代表实现其他来源或持久记忆的防护。

“改变后续行为”也不能独立作为攻击成立的条件：用户正常调整任务、偏好和自己先前的要求，应与覆盖受保护安全要求、伪造权限或把引用材料冒充指令区分开。检测依据不足以及检查未完成时，不能输出安全结论。

## Solution

以 OpenCode v2 的 session.prompt 作为本轮主检测入口。在用户正文进入附件与技能解析及持久化收件箱接纳之前，提取本次提交的原始文本，标记用户输入来源，交给独立文本引擎进行关键词、正则和一次 Jev 三分类判断。

参考 ATR 相关规则的攻击语义、匹配模式和正反样本，经过本地验证后转换为项目自有 YAML 规则。识别投毒企图或风险迹象，保留现有 benign、malicious、uncertain 汇总语义。正常任务调整不应仅因含有“忽略”“记住”“以后”等措辞就被判为攻击。

本轮只检测与告警，保留用户输入及提交语义，不自动改写、不自动阻断。不读取会话历史进行上下文关联，也不核验历史授权或跨轮攻击链。依赖缺失上下文才能确定的情况应归为 uncertain。

## User Stories

1. 作为 OpenCode 使用者，我希望新提交的消息正文进入投毒检测，以便在输入入口获知风险迹象。
2. 作为 OpenCode 使用者，我希望直接输入和通过用户 prompt API 提交的正文遵循同一检测入口，以便不同提交方式获得一致处理。
3. 作为 OpenCode 使用者，我希望经由用户 prompt API 提交正文的命令也经过检测，以便不会仅因提交方式不同而遗漏。
4. 作为 OpenCode 使用者，我希望原文在检测后保持不变，以便消息内容和我的原意一致。
5. 作为 OpenCode 使用者，我希望本轮告警不自动拒绝我的提交，以便先验证检测质量。
6. 作为 OpenCode 使用者，我希望正常修改任务和偏好被允许，以便可以自由调整自己的要求。
7. 作为 OpenCode 使用者，我希望正常撤回自己先前的指令不会仅因含有“忽略之前要求”而被判为攻击，以便能够纠正需求。
8. 作为安全分析者，我希望识别试图覆盖明确受保护安全要求的文本，以便发现越权操纵。
9. 作为安全分析者，我希望识别正文中的权限或身份伪造，以便消息中的自称身份不会自动提高其可信程度。
10. 作为安全分析者，我希望识别试图把引用内容提升为必须执行指令的文本，以便保护指令与材料之间的信任边界。
11. 作为安全研究者，我希望正常分析和引用攻击样本被区别对待，以便研究材料中的攻击措辞不会直接成为攻击结论。
12. 作为安全分析者，我希望记忆投毒不被定义为仅来自工具返回，以便领域概念能容纳不同来源的恶意植入。
13. 作为维护者，我希望本轮范围明确限定为用户正文，以便不会把领域概念扩大误解为其他防护已经实现。
14. 作为安全分析者，我希望参考 ATR 已有攻击模式，以便不从零罗列威胁样式。
15. 作为维护者，我希望 ATR 模式经过本地语义和正则验证后再使用，以便避免直接复制导致不兼容或误报。
16. 作为维护者，我希望记录借鉴规则的来源与版本信息，以便核查改编依据。
17. 作为安全分析者，我希望规则命中作为风险证据保留，以便可以检查原文匹配依据。
18. 作为安全分析者，我希望规则命中不直接证明投毒成立，以便保留模式与语义之间的冲突。
19. 作为安全分析者，我希望规则未命中时仍进行一次 Jev 判断，以便识别改写后的攻击表达。
20. 作为调用方，我希望正常、恶意和不确定三态能够传到运行时观察出口，以便不会在结果转换中丢失结论。
21. 作为调用方，我希望模型服务失败与模型合法返回 uncertain 可以区分，以便识别检测故障。
22. 作为 OpenCode 使用者，我希望超长正文被标记为未完成检测，以便不会误以为截断后的检查覆盖了全文。
23. 作为安全分析者，我希望缺少历史才能判断的消息保持不确定，以便不会把当前措辞当成历史授权已被核实。
24. 作为 OpenCode 使用者，我希望本轮不自动读取会话历史，以便检测范围与约定一致。
25. 作为安全分析者，我希望 malicious 和 uncertain 结果均有可观察提示，以便风险与检查不完整不会静默消失。
26. 作为 OpenCode 使用者，我希望告警不把完整消息、原文证据或凭据扩散到日志，以便减少额外内容泄露。
27. 作为部署者，我希望插件初始化复用已有 Jev 配置入口，以便继续使用既有配置项和进程环境优先级。
28. 作为部署者，我希望检测不可用被明确报告，以便插件加载或检查失败不会被误认为安全通过。
29. 作为维护者，我希望独立文本引擎继续与宿主 hook 分离，以便保留独立调用与评测能力。
30. 作为开发者，我希望通过现有插件入口和公开引擎入口验证行为，以便不为测试暴露内部实现。
31. 作为维护者，我希望未接入的工具、上下文和其他检测域继续明确显示未实现，以便能力描述真实。
32. 作为安全负责人，我希望区分风险企图、投毒成功和已阻断，以便检测结果不会夸大防护效果。

## Implementation Decisions

### 领域定义与本轮覆盖面

- 记忆投毒指通过向 Agent 的记忆或上下文植入、篡改或强化恶意内容，试图越过信任边界并影响后续判断与行为的威胁。工具返回污染是其中一种来源，不再作为领域定义的唯一载体。
- 本轮仅实现用户直接提交正文的风险检测；不承诺覆盖所有记忆投毒路径，不增加持久记忆文件防护。
- 用户明确授权本次范围变更。实施时同步当前领域术语、架构决策和能力说明，说明其替代旧的来源限定，不改写已完成任务以掩盖历史取舍。
- 投毒检测识别企图或风险迹象，不验证攻击成功，不提供已阻断的结论。

### 入口、正文与来源

- 主入口采用 session.prompt，使用官方 v2 的域 hook 注册方式。该 hook 在附件、技能解析和持久化收件箱接纳之前运行。
- 仅提取当前事件中 prompt 的文本正文，原样提供给引擎；由宿主适配层赋予明确的用户输入来源，不允许正文自称工具、系统或管理员改变其来源标记。
- 不拼接历史消息、工具输出、附件正文、技能内容或模型输出，不自动读取会话上下文。现有可选任务上下文字段不用于本轮历史关联。
- 用户输入来源本身不构成攻击依据。文本中自称更高权限、声称已获授权，也不自动建立可信权限或授权事实。
- 本轮不解析附件和技能；只有附件引用而没有正文时，不据此声称附件已经检查。正文为空与附件覆盖情况应如实说明，不伪造附件检测结果。
- 经由用户 prompt API 的命令提交适用同一入口。synthetic、shell 消息及压缩控制等不经此入口的操作，不列入本轮覆盖。
- hook 针对输入接纳执行，不在每次模型调用前重扫历史。沿用宿主的重试和并发接纳语义，不承诺 exactly-once 检测或告警，不为此新增全局去重存储。
- 不修改正文、文件、技能、agent 提及、metadata、delivery 或会话和消息标识，不把告警附加到用户消息或模型上下文。

### 引擎接入与生命周期

- 保留宿主适配、运行时路由、检测域和独立文本引擎的职责分离。宿主层负责 SDK 数据提取和告警出口，引擎仍只接收独立文本输入。
- 为记忆投毒检测域接入用户 prompt 路由，通过注入已初始化的引擎复用现有能力；不在该域另写关键词、正则或 Judge 实现。
- 插件显式初始化本地规则快照和 Jev 依赖，再处理输入。环境文件由既有显式配置入口读取，继续使用 JEV_API_KEY、JEV_API_URL、JEV_MODEL，已有进程变量优先。
- 不在引擎导入或每次检测时重新加载环境文件、重建规则快照；不读取或输出真实凭据用于验证。
- 沿用既有卸载和 hook 释放行为，不增加后台检测队列、持久会话状态或远程规则拉取。
- 现有其他记忆投毒 hook 路由不因本轮而获得工具返回或上下文检测能力；其占位结果仍应明确未实现。其他检测域不在本轮接入引擎。

### 判定目标与 Jev

- 判断原则属于可信检测配置，不能由待检正文改写。用户可以调整自己的任务、偏好及先前要求；覆盖明确受保护的安全要求、伪造更高权限或提升引用材料的指令地位，作为攻击嫌疑。
- 本轮不自动从项目文件、会话历史或正文声明中推导额外权限。不建立新的权限管理或安全策略配置系统；没有可信依据时，不能断言某条历史授权存在或某项具体操作已被禁止。
- 用户输入检测所用的判断指令与 Jev 类别描述应表达上述边界，避免当前较宽的“改变任务、权限或行为”表述将正常任务调整直接等同于攻击。
- Judge 仅使用 Jev 原生 Choice 三分类，不引入生成式解释、生成式证据、多模型兜底或额外模型调用。
- 对有效、未超限正文，每次引擎检测调用一次 Jev。无论规则命中与否，都不按规则数量增加请求；模式命中、评测标签和标注理由不作为 Judge 输入。
- 不引入置信度或概率阈值、检测超时、正则执行时限、自动重试、分块、解码或翻译流程。
- 不依赖会话历史验证“你之前同意”等说法，不提供跨轮关联能力。仅依据当前文本能识别的攻击迹象判断；必要事实缺失时返回 uncertain。

### ATR 参考与本地规则

- ATR 是威胁语义、匹配模式和正反样本的参考，不替换现有引擎，不自动导入整个规则库，不声称完整 ATR 兼容。
- 首批参考已阅读的用户直接注入和多轮注入规则。选取与当前正文及信任边界有关的模式，避免把正常任务切换、正常偏好、普通礼貌表达或历史引用直接当成攻击。
- 改编规则使用项目自有 YAML 模型和 LOCAL 命名空间；保留可追溯的上游链接与修订依据，可记录在规则说明或配套样本说明中，不为此扩展现有 YAML schema。
- 验证上游条件组合、字段目标和正则标志的实际语义后再改编。不直接把 ATR 的内联标志、复杂条件或 response 动作复制成项目可执行配置。
- 每个启用的改编模式应有对应的攻击样本和正常对照样本，覆盖中文使用场景；未完成本地验证的候选规则不能描述为已具备可靠覆盖。
- 上游名为“多轮”的文本规则，不能被描述为本项目已核验历史。匹配当前输入中的历史引用措辞只产生当前文本的风险证据。
- 沿用规则快照和版本机制，不新增热更新或远程下载。

### 结果传播与告警

- 对运行时结果契约作最小必要扩展，使三态结论、检查完成状态和程序性原因能够从引擎传播到告警出口；不能仅用 evaluated 或 findings 为空表达安全通过。
- 保留规则 ID、规则版本、阶段状态和已有规则证据；保留 Jev 原生分类及实际模型版本等引擎现有结果。程序性原因不称为模型解释，不伪造 Jev 的原文定位。
- 保持现有汇总语义，不因新增 hook 接入改成规则命中即 malicious：

| 条件 | 整体结论 |
| --- | --- |
| 输入无效或超出既有长度上限 | uncertain，标记未执行，不截断后宣称检查完成 |
| 任一必需阶段失败或未完成 | uncertain，保留已产生的发现与失败状态 |
| 检查完整且 Jev 为 malicious | malicious，无论模式是否命中 |
| 检查完整、模式命中而 Jev 为 benign | uncertain，保留模式与分类冲突 |
| 检查完整且 Jev 为 uncertain | uncertain，属于已完成的语义不确定判断 |
| 检查完整、模式未命中且 Jev 为 benign | benign，表述为本次正文未发现风险 |

- malicious 产生风险告警；uncertain 产生不确定或检查未完成提示，按实际阶段状态区分。benign 不触发风险告警，不宣称整个会话安全。
- 告警至少能关联本次用户输入的会话和消息，呈现检测域、三态结论及必要的程序性原因；内容日志不包含完整待检正文、匹配原文、认证头、配置值或真实凭据。
- 告警的具体承载通道尚未指定。实施时选用宿主可用的最小只读可观察出口，不把某种 toast、面板或日志系统视为已确认要求；必须能在公开入口测试中观察到对应输出。
- 检测异常、超长或 uncertain 不转化为拒绝提交。本轮不通过抛出安全拒绝异常、重写为空、修改 delivery 或权限策略实施隐式阻断。
- 初始化导致检测不可用时明确报告不可用，不能默认为 benign。宿主本身的插件加载或提交错误不包装成安全阻断能力。

## Testing Decisions

- 用户已确认测试边界：沿用现有插件 setup／hook 注册入口触发 prompt 回调，观察检测结果、告警和原始事件；引擎行为通过现有公开初始化与 detect 入口验证。不新增仅为测试暴露的私有函数接口。
- 以插件输入到可观察告警的集成边界为主，连接真实运行时和检测域、真实本地 YAML 与可控 Jev；独立引擎已有公开入口测试承接精细的分类与证据回归，避免在每层重复同一矩阵。
- 现有宿主适配测试可注册并触发 hook 回调、观察事件与卸载；现有运行时测试验证路由及占位状态；引擎测试已覆盖 YAML、规则快照、证据、长度边界和三态汇总；Jev 测试提供受控传输及本地 HTTP 服务先例。
- 不断言私有函数、内部对象布局或具体类名；通过消息正文、Judge 收到的公开请求、结果和告警等外部行为验证。
- 验证插件入口实际把 prompt 正文送入记忆投毒引擎，来源明确为用户输入，正常 API 和经由 prompt 的命令使用同一路径；不把伪造宿主事件测试等同于真实命令链已验证。
- 验证消息正文逐字保留，检测前后附件、技能、提及、metadata、delivery 与标识保持不变；无正文的附件输入不被描述为附件已检查。
- 在可控宿主中使历史上下文读取不可用或记录调用，验证本轮不读取会话历史、不抓取附件和技能，不把历史、规则命中或评测答案拼入 Judge 输入。
- 验证有效未超限输入每次检测一次 Jev；非法输入和超限不请求模型，不静默截断。沿用 Unicode 码点长度和 UTF-16 半开证据区间，覆盖含非 BMP 字符的正文。
- 覆盖正常任务修改、偏好设置、正常撤回要求、攻击样本引用，以及明确安全约束覆盖、权限伪造、引用材料提升为指令等输入。受控 Jev 测试验证判断配置和结果传递，不以预设返回值证明真实语义准确率。
- 对借鉴 ATR 的实际启用本地规则，以正反样本验证模式行为及来源记录，特别覆盖正常任务切换和正常历史引用；不得仅测试规则可被解析。
- 回归完整汇总表：无规则命中而 malicious、规则命中但 benign、原生 uncertain、技术失败、超限及完成且 benign，确保告警能区分风险、不确定和未完成检查。
- 验证网络异常和无效 Jev 响应不回传敏感错误正文，不改写或拒绝用户提交，也不触发第二次调用或备用模型。
- 验证配置或规则初始化不可用会明确报告，且不输出检测通过；日常测试仅使用临时环境文件和隔离测试值，不读取使用者真实环境文件或真实凭据。
- 验证告警可关联本次消息并保留必要状态，不包含完整正文、规则命中原文、认证头或配置值；不要求落盘全文审计。
- 回归其他 hook 和检测域仍然保持已声明的占位边界，卸载仍释放注册并取消公共事件订阅，HTTP 响应流不被本轮正文检测读取。
- 修改实现后运行 npm run typecheck 与 npm test。已有评测命令继续用于公开引擎评测；受控 Jev 或本地 HTTP 结果不得作为真实模型准确率证据。
- 真实 OpenCode v2 的插件加载、prompt 接纳与告警可见性需要独立宿主集成验证。未运行时必须标记未验证；真实 Jev 质量评测单独显式执行，不作为本规格发布已完成事项。
